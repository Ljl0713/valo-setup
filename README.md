# VALO SETUP

**无畏契约 4:3 拉伸 + 职业选手设置，一个窗口做完。**

纯 Python 标准库实现（ctypes + tkinter），不注入游戏进程、不读写游戏内存、不涉及任何作弊。

---

## 这是什么

把「无畏契约 4:3 拉伸」这件事从五六个步骤压缩成一次点击：

- **改分辨率** —— 一键在 4:3 和日常分辨率之间来回切
- **关黑边** —— 直接改游戏配置里的 letterbox 开关
- **写画质** —— 全屏、关垂直同步、Reflex、职业低画质，一次写入
- **关系统拖后腿项** —— 鼠标加速、粘滞键快捷键、GameDVR、电源计划
- **自动切换** —— 监听游戏进程，进游戏自动切 4:3，退游戏自动切回来

---

## 为什么不用现成的方案

网上多数 4:3 教程的前两步就有问题。

**① 「先去显卡面板建一个自定义分辨率」—— 大部分情况是多余的。**

主流显卡驱动本身就提供 4:3 模式。以一台 2560×1440@210Hz 的机器为例，
驱动原生支持 1280×960、1440×1080、1920×1440 等 8 个 4:3 档位，而且全都能跑到 210Hz。
这个工具启动时会直接枚举驱动真实提供的模式，你缺的从来不是自定义分辨率。

**② 「下个一键切换小工具，绑个全局热键」—— 热键会被抢走，而且它不报错。**

UU 加速器、显卡面板、壁纸软件都可能先占用 `Ctrl+Alt+数字`。
被抢之后工具安安静静地不干活，你只会以为「这玩意没用」。
所以这个项目不用热键，改成监听游戏进程。

**③ 真正卡住你的是这两处：**

- 游戏配置里的 `bShouldLetterbox`，默认 `True` —— 意思是「保持比例，多出来的地方加黑边」
- 显卡缩放模式默认「宽高比」—— 同样给你加黑边

两个都关掉，画面才会真正拉满。

## 功能

### 分辨率
- 自动枚举当前显示器驱动提供的全部模式，筛出 4:3 档位排成卡片（1280×960 优先）
- 任意自定义宽高，驱动不支持时明确提示而不是静默失败
- 刷新率自动跟随屏幕最高档，可手动锁定
- 多显示器：可选择在哪块屏上切换，选择会被记住
- 自动识别面板原生分辨率，不需要手动记录「日常模式」
- 切换**不写注册表**，注销或重启自动回到原生分辨率，不会因为忘记切回而卡在 4:3

### 游戏内设置
直接读写无畏契约自己的配置文件：

- 全屏模式 + 关闭垂直同步
- 真·拉伸（关闭 letterbox）
- 解除帧率上限
- NVIDIA Reflex 开 + 加速
- 职业低画质，**13 个键**：细节/材质/贴图=低、抗锯齿=关、各向异性=1x、阴影=关、泛光=关、失真=关、暗角=关、改善清晰度=开、实验性锐化=开、渲染缩放=100%

> 泛光/失真/暗角这几个键，玩家没动过设置时 ini 里根本不存在，所以不是"有才改"而是主动补写——否则永远不生效。

写入前自动备份，可一键回滚。游戏运行中写入按钮会自动禁用 —— 因为游戏退出时会把内存里的值写回文件。

### 一键去黑边

给不想碰显卡面板的人用的。点一下自动做完三件事：

1. 切到 4:3
2. 通过 Windows 显示接口（`SetDisplayConfig`）把缩放设成「拉伸填充」，不依赖显卡控制面板
3. 关掉游戏配置里的 letterbox 开关

如果显卡驱动接管了缩放（日志会明说），会按你的显卡品牌给出对应的手动步骤。
驱动里没有 1280×960 时，自动换成最接近的可用 4:3 档位。

### 系统优化
- 关闭鼠标加速（指针线性）
- 关闭粘滞键 / 切换键 / 筛选键快捷键
- 关闭后台录制 GameDVR
- 关闭全屏优化（走真独占，输入延迟低一档）
- 关掉 Xbox Game Bar 弹窗
- Windows 游戏模式
- 电源计划一键切最高性能

### 恢复全部默认

右上角「重置」一次撤销所有改动：分辨率回原生、缩放复位、系统项还原、游戏配置从最近备份恢复、软件设置清空。

**第一次点「一键全套」时会先存一份你机器原来的状态**，恢复时优先回到你自己的原值，而不是微软出厂默认——这样「本来就用卓越性能」这种个人习惯不会被抹掉。

## 快速开始

### 方式一：下载 exe

到 [Releases](../../releases) 下载 `ValoSetup.exe`，双击运行。不需要安装，不需要管理员权限。

> Windows 首次运行可能弹 SmartScreen「已保护你的电脑」，点「更多信息 → 仍要运行」。
> 本项目没有代码签名，这是所有个人开发工具的常态。

### 方式二：源码运行

需要 Python 3.10+，且带 tkinter（Windows 官方安装包默认包含）。

```bash
python ValoSetup.py
```

### 方式三：自己打包

```bash
pip install pyinstaller
python make_icon.py
pyinstaller --noconfirm --onefile --windowed --name ValoSetup \
    --icon valo.ico --add-data "valo.ico;." --version-file version.txt ValoSetup.py
```

## 三步上手

**1. 先把显卡缩放改成「全屏」（只做一次）**

NVIDIA 控制面板 → 显示 → 调整桌面尺寸和位置：

1. 缩放模式 = **全屏**
2. 勾选「**覆盖游戏和程序设置的缩放模式**」
3. 执行缩放 = **GPU**

AMD 显卡：驱动里「缩放模式」选「整个面板」，关闭「保持宽高比」。

4:3 能不能铺满屏幕由显卡驱动决定，这一步不设，切完就会有黑边。

**2. 点「1280×960」卡片**

程序会自动列出你这台显示器真正支持的模式，能点就说明支持。

**3. 让程序留在后台**

保持「自动切换」勾选，之后进游戏自动切、退游戏自动切回。窗口可以最小化。

## 工作原理

| 功能 | 实现 |
|---|---|
| 枚举分辨率 | `EnumDisplaySettingsExW` 遍历该显示器全部模式 |
| 切换分辨率 | `ChangeDisplaySettingsExW` + `DEVMODE`，带 `DMDFO_STRETCH` 尝试拉伸 |
| 原生分辨率 | 取该显示器模式表中面积最大的模式 |
| 多显示器 | `EnumDisplayDevicesW` + 按 `monitor_id` 记忆选择 |
| 刷新率降级 | 请求值不存在时按可用档位逐级下探 |
| 游戏进程检测 | `EnumProcesses` + `QueryFullProcessImageNameW` 匹配进程名 |
| 游戏配置 | 直接读写 `%LOCALAPPDATA%\VALORANT\Saved\Config\` 下的 ini |
| 配置写入 | 临时文件 + `fsync` + `os.replace` 原子替换，写后回读校验 |
| 系统项 | 注册表 `HKCU` + `SystemParametersInfoW` + `powercfg` |

**为什么不用注册表持久化分辨率**：持久化意味着用户切到 4:3 后关机，下次开机桌面还是 4:3。
本项目默认 `CDS_UPDATEREGISTRY=0`，注销或重启自动恢复系统默认。

## 常见问题

**切完 4:3 左右有黑边？**
显卡缩放没设成「全屏 + GPU」。见上面「三步上手」第 1 步。

**切完画面糊？**
4:3 拉到 16:9 是非整数缩放，必然有画质损失。想清楚一点用 1440×1080，想更宽用 1280×960。

**会不会封号？**
不会。改的是显示分辨率和游戏自己配置文件里的画质项，不读内存、不注入进程、不碰反作弊。

**为什么写入游戏设置没生效？**
先确认游戏已经完全退出。游戏运行中写入会被退出时的内存值覆盖。

**杀软报毒？**
PyInstaller 打包的 exe 有概率被启发式引擎误判。加入信任即可，源码全部开源可自行审计。

**桌面图标位置乱了？**
Windows 在分辨率切换后的正常行为，切回原生分辨率会恢复。

**程序在后台占多少资源？**
单文件版常驻约 38 MB 内存，每 1.8 秒轮询一次进程列表，CPU 占用接近 0。

## 项目结构

```
ValoSetup.py      入口：单实例检查 + 异常兜底
valo_core.py      显示核心：多显示器 / 模式枚举 / 安全切换
valo_game.py      游戏配置：多路径探测 / 原子写 / 校验 / 备份
valo_sys.py       系统优化项
valo_state.py     配置持久化 / 日志 / 单实例 / 诊断导出
valo_app.py       界面层
make_icon.py      生成应用图标（纯 Python 手写 ICO）
version.txt       Windows 版本信息资源
```

配置与日志位置：`%LOCALAPPDATA%\ValoSetup\`
游戏配置备份：`%LOCALAPPDATA%\ValoSetup\backup\<时间戳>\`（保留最近 10 份）

程序内按 **F1** 可导出诊断信息（系统版本、DPI、显示器模式表、配置路径、日志尾部）。
